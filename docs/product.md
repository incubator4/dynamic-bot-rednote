# 产品：小红书来源插件

## 一句话

让 dynamic-bot 能订阅小红书用户，把新笔记渲染并推送到已配置的消息出口（例如 QQ / OneBot）。

本仓库只交付 **一个** 内容来源插件的 fatJar。登录、轮询、发布者资料、笔记映射、链接解析都发生在这个插件里；订阅关系、绘图、投递、重试、撤回由主程序负责。

## 用户能做什么

1. 在 Web 后台启用本插件，用自己的小红书 Cookie 完成登录。
2. 用小红书用户 ID 添加发布者，并绑到已有消息目标。
3. 插件检测到新笔记后，交给主程序推送。
4. （一期宜做）聊天里出现小红书链接时，解析成预览或动态卡片。

## 一期（MVP）

必须有：

- Cookie 登录与登录态检查；未登录 / 风控时暂停轮询。
- 按用户 ID 查询发布者资料（昵称、头像、主页）。
- 轮询已订阅用户的新笔记（图文 / 视频笔记都映射成动态，不先做独立直播源）。
- 用 `DynamicPayload.blocks` 按平台原始展示顺序建模。
- 游标去重：启动默认不补发旧笔记。
- 插件配置表单（中文）：轮询开关、轮询间隔、请求间隔、补发窗口、未登录暂停阈值。

应该有：

- 解析 `xiaohongshu.com` 笔记 / 用户主页，以及 `xhslink.com` 短链。

## 明确不做（一期）

- 不当主程序，不实现 `MessageSinkPlugin`。
- 不把订阅列表、消息目标、绘图主题做进本插件。
- 不默认做用户名搜索、自动关注、二维码登录、视频下载、直播开播提醒。
- 不打包独立可运行 Bot，不引入第二套命令或投递通道。
- 不提交 Cookie、抓包会话或绕过平台风控的实现说明。

后续能力（搜索、关注、二维码、直播、视频下载）只有在对应 ADR 被接受后才开工。

## 使用约束

小红书接口比一般资讯源更敏感。默认策略对齐微博插件：轮询可默认关闭或间隔偏长；连续请求必须留间隔；登录失效立即停手，而不是加大重试。
